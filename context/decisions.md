# Decision log

Newest last. Earlier HTML-prototype decisions (live mirror, keyboard styles, design-system divergences, …) are in `seedsigner-touchscreen/docs/00-plan.md` › Decisions log; the design-system ones carry over unchanged ([design-system.md](design-system.md)).

| Decision | Choice | Why | Date |
|---|---|---|---|
| Where the redesign lives | This fork of kdmukai/seedsigner-lvgl-screens, as an **additive** `components/seedsigner/redesign/` beside the untouched Classic screens | Keeps upstream merges clean; pieces can be offered upstream later | 2026-10-16 |
| Names | **Classic** = upstream landscape design; **Redesign** = easyuxd portrait design | Plain words for designers | 2026-10-16 |
| What the Redesign is | A **clickable prototype with demo data**, not a working wallet | A wallet means rewiring the SeedSigner Python app, a separate, much larger project | 2026-10-16 |
| Responsive model | Points on a 320 pt canvas × (width ÷ 320); LVGL flex for layout; **the screen type owns where spare height goes** | Mirrors CSS rem + flexbox; one design for 320×480 and 480×800 | 2026-10-16 |
| Capturing responsive rules | In code (six shells) **and** in design-system.md §2 | Rules can't drift from what runs, and designers can read them | 2026-10-16 |
| "CSS" for LVGL | `tokens.json`, loaded at runtime (hot-reload in the browser) | LVGL 9.5 dropped its open-source XML UI loader, so tokens + C components are the clean equivalent | 2026-10-16 |
| Screens as data | Screens are JSON (`prototype.json`) composed from C components; C only for new *kinds* of component | Layout and copy changes hot-reload like HTML; C stays small and reviewable. Refines the earlier "screens in C" sketch | 2026-10-16 |
| Fonts | Runtime TrueType (tiny_ttf) for all Redesign text and icons; icon OTF converted to TrueType outlines by `scripts/redesign/build_fonts.py` | Any size renders crisply, which is what responsive type needs; stb_truetype can't read CFF | 2026-10-16 |
| Bold weight | Renders as SemiBold for now | No static Bold face yet; tiny_ttf ignores variable-font axes. In the backlog | 2026-10-16 |
| Browser tool | Extend the existing web_runner with a **Classic \| Redesign** switch; Redesign gets its own studio page | One tool, same engine, same Pages site | 2026-10-16 |
| Two sizes side by side | One engine instance per size (iframes), synced by navigation path | The engine has one display; separate instances keep it simple and both interactive | 2026-10-16 |
| Inspector | Read-only in PR 1 | YAGNI until the system is stable; v2 (annotate, live tokens, redlines) is in the backlog | 2026-10-16 |
| No Docker | Native Emscripten **3.1.74** in `~/emsdk` (official emsdk), installed by the studio | Same version CI pins; Homebrew's Emscripten (6.x) hits a documented break | 2026-10-16 |
| Classic locales locally | `stage_assets.py --available-only` (opt-in) | The language-packs repo isn't needed to design; CI behavior is unchanged | 2026-10-16 |
| Scope | English-only, touch-only Redesign | YAGNI; both are in the backlog | 2026-10-16 |
| Unported destinations | Info snackbar "Not ported to LVGL yet", without muting | Keeps screens looking as designed; `muted` stays reserved for what the prototype marks unavailable | 2026-10-16 |
| Sequence | PR 1 (studio + foundation screens + docs) → PR 2 (builder fork, device lane) → test on 4.3″ → flash 3.5″ → port remaining flows | Smallest reviewable steps; the browser first | 2026-10-16 |
| HTML prototype repo | Read-only visual reference until parity, then archived | One place to work, one to compare against | 2026-10-16 |
| Docs | Root `AGENTS.md` router + `/context/` (ez-context convention); upstream `docs/` untouched | Agents and humans read the same layer | 2026-10-16 |
| Comparing devices | Two pickers (Device 1, Device 2) over a small device catalog; None in a slot shows one device centred; selection kept in the URL | Compare any two boards, or focus on one, without a page per board | 2026-10-16 |
| Device catalog | Real boards (Waveshare 3.5″, Waveshare 4.3″, Guition 4.3″) plus the engine's existing 720p size; no guessed specs (the Waveshare 5″'s resolution isn't documented yet) | Each studio size must be the portrait of an engine display profile | 2026-10-16 |
| Homebrew Emscripten | `studio.sh` refuses to start if the `emcc` on PATH isn't the pinned `~/emsdk` one | A new machine can't silently build with the wrong version | 2026-10-16 |
| Device UI choice | One firmware; NVS `seedsigner`/`ui` read at power-on picks Classic (landscape) or Redesign (portrait); `tools/set_ui.py` switches over USB | Orientation is fixed at `board_init()`, so the choice must be known before Python runs; no reflash to switch, and portrait is the 4.3's native (faster) orientation | 2026-10-16 |
| Native firmware build | `scripts/native_build.sh` with ESP-IDF v5.5.5 in `~/esp/esp-idf-v5.5.5`; MicroPython patches applied without a commit (`MP_PATCH_NO_COMMIT=1`) | No Docker; the upstream throwaway commit uses a fixed `builder@localhost` identity that this machine's account hooks rightly refuse | 2026-10-16 |
| The 3.5″ mirror | Retired: the 3.5″ runs the builder firmware (PRE_REV3) with the Redesign, like the 4.3″ | One design on one engine across both boards; the HTML prototype stays in its repo as the visual reference | 2026-10-17 |
| Press states | Option A of three explored (`explorations/press-states-lab.html`): color instant on touch-down, scale 0.97 in 30 ms, release 140 ms (ease-out), minimum press 80 ms from touch-down; `surfacePress` `#393939`, `activePress` `#EB9209`; selected choice presses to `activePress`; transparent controls fill their shape with no white flash | The boards are slow, so the touch-down must snap (Emil Kowalski: press feedback 100–160 ms, response snaps, release softer); lighter-on-grey and darker-on-orange follow the content-color rule and stay visible on cheap IPS panels; the minimum lets every tap show its press without slowing normal taps. Quiet chosen over Balanced (0.95, `#454545`) and Ringed (Balanced + outline) | 2026-10-17 |
| PSBT demo data | One transaction ("Standard spend") ported end to end; the other three and their screens wait | YAGNI; every component and dialog is still built, and the dialogs open from the Screens list | 2026-10-17 |
| PSBT branching | Generic `set` tap key + `{state}` in `go` + a screen `auto` step, instead of PSBT-specific runtime code | Lets Select Signer decide where signing ends (success or Sign Failed) with plain JSON; reusable by later flows | 2026-10-17 |
| Fee-share rule lives in `tx_card` | Computed from the rows, not set per screen | A safety rule a screen author can't forget (design-system §12) | 2026-10-17 |
| The Math's change line | `fg1` with a rule above it, not orange as in the prototype | Orange doctrine: orange is focus, selection or live input, never emphasis | 2026-10-17 |
| Signer row status copy | "Signs this transaction" / "Not in this transaction" (prototype: "Key found in this transaction" / "Not an input of this transaction") | The prototype copy doesn't fit the 48 pt row beside the icon and status mark; shortened, not widened (content rule) | 2026-10-17 |
| PSBT screen layout | The `review` shell anchors content to the top; the prototype centred Math and Will Send between flexible spacers | Screen types own spare height (design-system §2); a new placement rule would be a design decision | 2026-10-17 |
| Design Studio redesign | The studio views **and** edits: canvas of every screen by flow, Design / JSON / Comments tabs, Tokens panel, comments sent to an agent in batches, version history, undo/redo, frame-rate dial. Supersedes "Inspector: read-only in PR 1". Guide: [design-studio.md](design-studio.md) | Iterate in one tool: see every screen, change it, feel it, and hand feedback to an agent without leaving the studio | 2026-10-18 |
| Studio direction and layout | **A · Docked** and **Design + Prototype** (⇧E), chosen in `explorations/design-studio-lab.html` over B Floating, C Rail and a Workspace layout with a Play overlay; the mode switch sits right of centre, left of Undo, so it never moves | Fixed panels are calm and predictable; separate modes give the live devices the whole canvas while the panels stay useful | 2026-10-18 |
| Studio edits | Saved straight to the JSON files through the studio server, applied to the file on disk, in the files' own formatting; tokens only for styling | The devices, the canvas and agents all read the files, so a pending "Save" step would leave them stale; tokens keep one source of styling (raw values: backlog trade-off) | 2026-10-18 |
| Undo vs. history | ⌘Z undoes only your studio edits; every save (yours, the agent's, any outside edit) is a version, stored in `.studio/` (gitignored); agent versions carry an Agent badge | Undo never surprises you by reverting agent work; history rolls anything back or forward | 2026-10-18 |
| Comments to agents | Saved locally and sent as a batch; the agent reads and answers them with a CLI (`studio_comments.py`) when asked to "address the Design Studio comments", so no agent has to be watching | Async and dependency-free; works with any agent | 2026-10-18 |
| Frame-rate dial | In Prototype mode, the engine's main loop draws only N frames a second (60 / 30 / 15 / 10) | Feel a slow board in the browser, as the press-states lab did, with the real engine | 2026-10-18 |
| Studio saves are surgical | The server parses the JSON with source spans and rewrites only the changed values' text (new values in the house style), instead of re-formatting the file | The files are hand-formatted (aligned token tables, wrapped components); a formatter that reproduces that exactly is fragile, and surgical edits keep git diffs to the lines that changed | 2026-10-18 |
| Styling numbers in screens | Shown as "not a token" and not editable in the Design tab (tile `h`, spacer height, `tracking`); tokens are edited in the Tokens panel, which has **New** | A part can't reference a token by name yet (the C reads plain numbers), so a token picker there would be a fake; letting parts name tokens is in the backlog | 2026-10-18 |
| Canvas pictures | One hidden engine per canvas size renders every screen to a PNG from its frame buffer, with every part's box (`ss_rd_outline`), re-rendered on each data change | 20+ live engines would be heavy; this is how the gallery already works, and it gives exact hit-testing | 2026-10-18 |
| Slide to sign | The **whole bar** (plus a 10 pt claim above and below) grabs; reaching **75%** signs on the spot, or at release for a flick; a tap plays a **nudge**; the chevrons **pulse**; boards read touch every 10 ms. Chosen over "+ press-and-hold" and "hold to sign" (interview with draggable mockups) | On the boards the old version (grab the 50 pt thumb only, let go past 90%) failed often: touches on the label did nothing, and lift jitter sprang it back. One deliberate ~170 pt drag still can't come from a pocket; two ways to sign would be more to learn and test | 2026-10-19 |
| Bold weight (supersedes "Renders as SemiBold for now") | Open Sans Bold 3.003, baked Redesign-only (`rd_ui_bold.c`), used only where the prototype uses 700 | The prototype's emphasis (badges, dire label, tags) was flattened to SemiBold; Classic stays untouched | 2026-10-19 |
| Breathing border | Added by the shell to any `dialog` whose body has a warning, dire or error `message` | A rule a screen can't forget, like the fee-share warning; also covers the PSBT dialogs | 2026-10-19 |
| Remaining flows | All seven ported in one PR, one commit per flow: QR transport, seed backup, discard, load/create seed, passphrase with all four keyboards, export Xpub, BIP-85 (40 screens; the canvas has 55) | Settings › Keyboard already offered four styles; the canvas pins the other three for comparison | 2026-10-19 |
| Demo counts | Word entry asks for **3** words and dice for **6** rolls; the navbar subtitle says what a real seed needs | Quick to try the redesign; the full flow is in the backlog | 2026-10-19 |
| Keyboard geometry | In `rd_input.cpp` as the prototype's measured points, scaled with `pt()`; colors and timings are tokens | ~40 tuned numbers per style; tokens would add names nobody edits alone (the same reasoning as `tx_card`'s columns) | 2026-10-19 |
| Scanner | Simulated (frames, received, hand-off; a tap skips ahead); idle and unrecognized states pinned on the canvas. Real camera wiring is in the backlog | The boards have no camera wired up | 2026-10-19 |
| Screens that move on by themselves | Their hand-off uses `"replace"`, so Back skips them | In the prototype, Back from Select Signer went into the scanner, which scanned again and pushed you forward: a loop | 2026-10-19 |
| Seed detail | Shows the seed in state (`seed_fp`, `seed_sub`); seed rows, Finalize and the passphrase review set it; `"go": "home/seed"` resets the back stack | New seeds and passphrase wallets lead somewhere real without a seed-list model (still in the backlog) | 2026-10-19 |
| Prototype departures in the remaining flows | Quiz: right answer `success` green (prototype orange). Dice: "N more rolls to go" as text, Generate appears at the count (prototype: a dead button). Finalize: fingerprint icon `fg1` (prototype orange; its own tweak defaults to Neutral). Discard: the shared `message` dialog (warning, breathing) with `cta` `dire` (prototype: its own layout and a text button), and the body states the consequence. Copy: "Classified info", "Privacy leak", "I understand", "Check your backup?" without "mnemonic", `&` not "and", no "!". Seed Words: title + "1 of 3" subtitle. Signed QR: no Back (signing is done). Word entry: Back returns to the word count, not the previous word | Orange doctrine, never a dead button, one dialog component, and the content rules in design-system.md | 2026-10-19 |
| Where upstream differences live | [redesign-changes.md](redesign-changes.md), by area, upstream values cited from Classic's `gui_constants`; the design system links to it instead of keeping its own divergence table | One list to take upstream once the design is final (backlog) | 2026-10-19 |
